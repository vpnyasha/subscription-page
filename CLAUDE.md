# Kimiko — форк remnawave/subscription-page

Страница подписки Remnawave с собственным оформлением. Апстрим (`upstream`) —
`remnawave/subscription-page`, наш форк — `vpnyasha/subscription-page`, главная
ветка `kimiko`.

Правки апстрима стараемся не размазывать: тема, брендинг и декор вынесены в
отдельные файлы, чтобы слияние с апстримом оставалось посильным.

## Стек

Vite 8 + React 19 + React Router, Mantine 9, FSD-структура (`app / pages /
widgets / entities / shared`). SSR нет. `index.html` — EJS-шаблон, данные
подписки бэкенд вставляет base64-строкой в `<div id="sbpg" data-panel="...">`,
их разбирает `app/layouts/root/root.layout.tsx`.

## Тема

- `shared/constants/theme/palette.ts` — палитры `kimikoAccent` / `kimikoSand`
  и семантические цвета `kimikoColors` (поверхности, границы, `track`, `body`).
  Единственный источник правды и для CSS, и для TS.
- `shared/constants/theme/css-variables-resolver.ts` — оборачивает
  `v8CssVariablesResolver`, объявляет токены `--kimiko-*` и переопределяет
  `--mantine-color-body/text/dimmed/default*`.
- Тема только светлая (`forceColorScheme`), `<meta name="color-scheme" content="light only">`.

Цвет `kimikoColors.body` подобран по среднему цвету фоновой картинки
(`#e5dacf`). Это не эстетика, а требование: заливка холста должна совпадать с
картинкой, иначе на стыках видны полосы.

## Брендинг

- `shared/constants/branding.ts` — `BRAND_LOGO_URL`, логотип захардкожен на CDN
  (панель отдаёт логотип Remnawave, он тут не нужен). Тот же файл — в favicon.
- `shared/constants/labels.ts` — `ACCOUNT_LABEL = 'ID'`. В `baseTranslations`
  под этим ключом лежит «Имя пользователя», но у нас в `username` — Telegram ID,
  поэтому подпись живёт в коде форка.

## Блок подписки

`widgets/main/subscription-info/subscription-info-hero.widget.tsx` — единственный
вид блока. В `main.page.component.tsx` все варианты из конфига панели (`cards`,
`collapsed`, `expanded`) отрисовываются им же; `hidden` по-прежнему скрывает
блок. Апстримные три виджета лежат рядом и не используются.

Что важно знать про данные:

- **Остаток считается по `expiresAt`, а не по `daysLeft`.** В последние сутки
  панель отдаёт `daysLeft = 0`, и подписка выглядела бы истёкшей. Меньше суток
  показываются часы, меньше часа — минуты.
- **Активность берётся из `user.isActive`**, панель считает его сама.
- Склонения («359 дней», «16 часов») делает `Intl.NumberFormat` со `style: 'unit'`
  — работает в любой локали, свои словари не нужны.
- **Период оплаты угадывается**: панель не отдаёт дату начала подписки, поэтому
  берётся ближайший сверху типовой срок из `[31, 93, 186, 366, 732]` дней. Это
  эвристика, а не факт: месячная подписка за 5 дней до конца показывает ~16%,
  годовая в первые дни — почти 100%.
- Полей про устройства в контракте нет — строки «Устройств N из M» быть не может.

Кнопки «Скопировать ссылку» и QR живут здесь же; в шапке остаётся только
поддержка (`hideGetLink` передаётся жёстко), иначе кнопки дублировались бы.

## Декор

Ассеты — `public/assets/decor/`: `background.webp` (подложка), `left.webp`,
`right.webp`, `left-flip.webp` (зеркальная левая), плюс SVG-мелочь (`flower`,
`dots`, `cross`, `spark`).

- **Широкий экран**: подложка — фиксированный слой `.animated-background`,
  фигуры — `body::before` / `body::after` по краям.
- **Узкий экран (≤1100px)**: фоновые фигуры выключены, вместо них одна фигура
  выглядывает из правого верхнего угла **только карточки подписки**
  (`theme/overrides/card/card.module.css`, `:nth-of-type(1)`).
- **Чередование**: `root.layout.tsx` при загрузке пишет
  `document.body.dataset.kimikoDecor = 'left' | 'right'`, CSS по этому атрибуту
  выбирает картинку — фигура меняется от захода к заходу.
- Орнамент внутри карточек (цветок, точки, крестик, искра и вертикальная подпись
  `キミコ`) рисуется псевдоэлементами `.root::before/::after`. Карточка имеет
  `isolation: isolate`, а содержимое — `z-index: 1`, иначе орнамент лезет на текст.

## iOS 26 Safari — не сломайте прозрачные бары

Самая хрупкая часть. В Safari 26 верхний и нижний бары («Liquid Glass»)
тинтятся так:

1. берётся `background-color` ближайшего к краю экрана `fixed` или `sticky`
   элемента;
2. если такого нет — `background-color` **body**;
3. `<meta name="theme-color">` **игнорируется** (поэтому его в `index.html` нет).

Отсюда набор правил, которые выглядят странно, но держат прозрачность:

- `body` — **всегда `background: transparent`**. Цвет холста держит `html`,
  его Safari не сэмплит. Стоит вернуть заливку на `body` — бары станут сплошными.
- Заливка также продублирована на `#root` — обычный элемент, его цвет не
  сэмплится, зато он закрывает страницу целиком.
- На телефоне **фиксированного слоя фона нет**: `.animated-background` скрыт,
  картинку рисует `#root` (`background: url(...) center top / cover`). Плата —
  фон едет вместе со страницей. Вернуть `fixed` = вернуть непрозрачные бары.
- Шапка на телефоне — `position: relative` (не `sticky`!) и `top: 0`.
  - `sticky` красит статус-бар в кремовый;
  - `static` ломает вёрстку: фон шапки рисует **абсолютный псевдоэлемент**
    `.header-wrapper::before`, и без позиционированного родителя он
    растягивается на всю страницу (проверено: 1470×1644 вместо 736×76);
  - `top: 0` обязателен, иначе унаследованный от `sticky`
    `top: calc(env(safe-area-inset-top) + ...)` сдвигает шапку вниз и она
    съедает отступ до первой карточки.
- Фон шапки вынесен в `::before` именно потому, что фон на самом `sticky`
  элементе тинтит бар.
- `viewport-fit=cover` + `env(safe-area-inset-*)` у `.content` — чтобы контент
  не лез под вырез. `apple-mobile-web-app-status-bar-style: black-translucent`
  работает только в PWA-режиме («На экран Домой»), в обычной вкладке — нет.

Прочее по мобильной вёрстке:

- Высоты — `svh` (не `dvh`: он дёргается при движении панели браузера).
- `overscroll-behavior-y: none` — оттягивание страницы обнажало бы пустоту.
- Вертикальные отступы шапки заданы в CSS, а не пропом `py` — Mantine ставит
  `padding-block` инлайном, и медиазапросы его не перебивают. Та же ловушка с
  любыми style-пропами Mantine.

## Заглушка

Открыт голый домен без ключа — панель не подставляет данные, и раньше висел
вечный спиннер (в проде — белый экран). Теперь `root.layout.tsx` разделяет:
нет конфига → спиннер, конфиг есть и нет подписки →
`shared/ui/subscription-missing/`. Тексты (ru/en, фолбэк на en) лежат в самом
компоненте — в `baseTranslations` такого ключа нет.

## Локальный запуск

```bash
npm run dev:fixtures        # генерит dev-fixtures/app-config-v2.json и .env с PANEL_DATA
npm run start:dev -- --host 0.0.0.0   # http://localhost:3334, с телефона — по IP машины
```

- Фикстура лежит в `dev-fixtures/`, а не в `public/`, и отдаётся dev-плагином
  `devAppConfig()` из `vite.config.ts` — в прод-сборку она не попадает.
- Имена серверов в `PANEL_DATA` должны быть percent-encoded: `atob` не понимает
  UTF-8, эмодзи-флаги ломаются (панель делает так же).
- Чтобы проверить редкое состояние (истечение через N часов, отсутствие
  подписки), правьте `PANEL_DATA` в `.env` и **перезапускайте dev-сервер** —
  на лету `.env` не перечитывается.

Проверка перед коммитом: `npx tsc --noEmit -p tsconfig.json` и `npx eslint src`
(в `root.layout.tsx` есть одна унаследованная от апстрима ошибка сортировки
импортов).

## CI/CD

`.github/workflows/build-and-push.yml`: сборка фронта → multi-arch образ
(amd64/arm64, push-by-digest) → `docker buildx imagetools create`. Только GHCR,
`secrets.GITHUB_TOKEN`, имя образа приводится к нижнему регистру.

Релиз — пуш тега: `git tag 7.2.6-kimiko.N && git push origin 7.2.6-kimiko.N`,
образ получает `:latest` и `:<tag>`. Запуск вручную по ветке даёт `:<branch>`.

Коммиты подписываются `Co-Authored-By: Fable5 <noreply@anthropic.com>`.
